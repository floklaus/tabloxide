Analyze the execution plan of this statement. Suggest improvements.

select * from item
where price > 10
order by created_at desc

Plan from EXPLAIN (estimates only)

Sort  (cost=1840.12..1862.40 rows=8912)
  Sort Key: created_at DESC
  ->  Seq Scan on item  (cost=0.00..1255.00 rows=8912)
        Filter: (price > '10'::numeric)

The sort is the step with the highest cost. The database reads the full table, then sorts the rows that pass the filter. An index on created_at lets it read the rows in the sort sequence.

CREATE INDEX CONCURRENTLY item_created_idx
  ON public.item (created_at DESC);

The plan has estimates only. Measure the times to see if the filter or the sort takes longer.
