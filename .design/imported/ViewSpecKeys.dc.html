Keyboard, states, and examples

A person can do each task in a view with the keyboard only. The keys are the same in each view. The trees and lists follow the WAI-ARIA tree and listbox patterns.

6. Keys in a tree or a list

KeyAction
↑ ↓Move the focus one row. The detail does not change.
→Open a closed node. On an open node: move to its first child.
←Close an open node. On a closed node or a leaf: move to the parent.
Home End PgUp PgDnMove to the first row, the last row, or one page.
SpaceShow the detail in the preview tab. The focus stays in the view. In a row with a check box (Git changes), Space sets or clears the check box.
EnterDo the primary action of the row: open the table, connect, open the file, open the diff. The tab stays open and gets the focus.
Ctrl+EnterDo the second action: query the first 100 rows, run the history entry again, commit.
F2Rename in place: file, snippet, connection, branch. Enter keeps the name. Esc cancels. Views without rename ignore F2.
DeleteDelete or discard the row. A confirmation names the object and the result. Focus then goes to the next row.
F5Read the data of the view again.
Shift+F10 or Menu keyOpen the context menu. It has the same actions as the overflow menu, with their shortcuts.
Letters, digitsType-ahead: move to the next visible row that starts with the typed text. The buffer clears after 0.5 s. Type-ahead does not filter.
Ctrl+F or /Move to the filter field of the view. ↓ moves back to the first match.
EscIn the filter: clear the text. A second Esc moves the focus to the list. In the list: close the preview tab.
Shift+↑↓, Ctrl+clickSelect more than one row, where the view supports it (Git changes, files, history).
Ctrl/⌘+KOpen the command palette from any place. @ finds schema objects. Each view action is also a palette command.

On macOS, Ctrl is ⌘ in each shortcut above. Mouse: a single click is Space. A double click is Enter.

7. Focus order

Tab moves between parts. Each part is one Tab stop. In a list, the arrow keys move between rows (roving tab index).

  1. 1Scope menu
  2. 2Primary action, then overflow menu
  3. 3Mode tabs (if the view has modes), then the filter field
  4. 4Tree or list: the last focused row
  5. 5Bottom box, if the view has one (commit message)
  • When a view opens, the focus goes to part 4.
  • F6 moves to the next area of the window: side view, editor, lower panel, assistant.
  • When a row goes away (delete, filter), the focus goes to the next row, else to the previous row.
  • The focus ring is 2 px, colour #2563eb (dark: #60a5fa), 2 px from the row. Never remove it. Neon and High contrast: see part 3.

8. Empty, loading, and error states

Each view defines these four states. The header and the toolbar stay in their place in each state. Only the body changes. The Schema states artboard shows them in full.

Empty: no source

The view has nothing to show yet. Say why in one sentence. Give one button that fixes it.

The tab has no connection.
Select a connection

Empty: no match

The filter hides all rows. Show the filter text. Give a button that clears the filter.

No table contains "invoice".
Clear the filter

Loading

Wait 300 ms. Then show skeleton rows at the row height. The status line says what loads. Rows that are already there stay.

Error

Show the error at the top of the body. Say what failed and what to do. Give Try again. Keep old data, and mark it as old.

Cannot read the schema. The server closed the connection.
Try again

  • A node that loads or fails shows one inline row under that node. The rest of the tree stays usable.
  • An error has role="alert". A loading message has role="status". Do not use a toast for an error that needs an action.
